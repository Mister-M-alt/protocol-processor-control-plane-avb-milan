[A157] MATERIAL DECISIONS (implementation head `ea93023fbdd31cbf718da0d8f1aab4d750bfd21a`, local and unpublished)

1. **Name.** The public parameter is `SRP_DOM_DEF_VID_P` (`logic [15:0]`, default `16'd2`), registered as `P-SRP-DOM-DEF-VID` in 01 §7 F01.5. The `SRP_` prefix scopes it among the top's engines and keeps it apart from gPTP's `gptp_domain_i`. The rest is the child's own `DOM_DEF_VID_P`, so the binding reads one to one: `.DOM_DEF_VID_P (SRP_DOM_DEF_VID_P)`. The P-ID follows F01.5's convention of mirroring the RTL name.
2. **No engine change.** `hdl/srp/` is untouched. The child keeps its 16-bit width and its own default of 2. The only RTL change is the declaration and one explicit binding in `hdl/top/protocol_processor_top.sv`.
3. **No elaboration guard.** The top does not refuse non-2 values: the verification fixture needs one, and elaboration behaviour stays unchanged. Refusing other shipping defaults belongs to the parent builder, per the #400 decision. The donor documents "keep it at 2 in a product build" in F01.5, the integrator guide and the parameter banner.
4. **Documentation.** New F01.5 row. F10.2 now cites `P-SRP-DOM-DEF-VID` instead of repeating the value, because `docs/README.md` §2 allows parameter values only in F01.5. Additions in 10 §11 and integrator guide §2 (the parameter row) and §8 (link-down restores the defaults). Deliberately unchanged: `docs/guides/operator.md` ("VLAN 2" is true for every product build), and diagram 21's shape box, which is a summary rather than a parameter list.
5. **Test shape.** `tb/pp_top` builds twice. The first build overrides nothing, so it grades the top's own default, and runs every section plus the new section DV. The second build overrides the top with the verification-only fixture `0x5A3C` and runs DV alone. DV runs on a fresh model in both builds: reset value, LINK_UP declaration byte-exact, GET_DOMAIN, snapshot word 10, GET_TX_STATE VLAN, bridge Domain adoption (Lv of the default, New of the adopted), LINK_DOWN revert and LINK_UP re-declaration.
6. **Fixture value.** Every plausible fault on `0x5A3C` gives a distinct value: missing or literal (2), 8- or 12-bit truncation (0x003C, 0x0A3C), byte swap (0x3C5A), or routing to the priority (reads 4). Its low 12 bits (0xA3C) are a legal VID; only the 16-bit MSRP field shows the top nibble. The C++ expectation is compiled from the same Makefile variable and is never read back from the DUT.
7. **Tally.** Each binary prints a per-build line. The Makefile sums both into the one canonical `N checks: N PASS, N FAIL` line that `run_suites.sh` reads. This is the `tb/dyn_state` precedent; the tally file lives under git-ignored `obj_dir/`, and a missing build tally fails the suite.
